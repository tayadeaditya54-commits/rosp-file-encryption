2. Problem Overview — Input Component Defects

Reviewing layout overlap, disabled state disconnect, and accessibility flaws
What is the problem?

In InputBase, the eye toggle button is positioned absolutely at the trailing edge. However, trailing padding calculations only checked tooltip and isInvalid, completely omitting password fields. Consequently, long passwords collide with and scroll underneath the eye toggle.

Why does it matter?

Obscured passwords hurt usability and privacy verification. Furthermore, disabled inputs left the toggle button clickable, lacking dynamic screen reader announcements and risking unintended form submissions.

Specific Defects Identified in Codebase
  • ✕
    Text Overlap on Passwords: Characters flow into the trailing icon bounds because pr-9 padding was not allocated.
  • ✕
    Interactive Toggle on Disabled Input: The eye button remained clickable when the input field was disabled.
  • ✕
    Missing Dynamic ARIA & Type: No aria-label or type="button", causing screen reader silence & form submit risks.
  • ✕
    Type Pollution in InputNumber: Stale copy-pasted date type imports polluted IDE autocompletion.

5. Implementation Steps

What was changed in the React component logic
Target: components/base/input/input.tsx
1. Factored password type into trailing detection:
const hasTrailingIcon = Boolean( tooltip || isInvalid || type === "password" );
2. Dynamic right padding allocated in size matrix:
md: { root: cx("px-3 py-2 text-md", hasTrailingIcon && "pr-9"), iconTrailing: "right-3" }
3. Upgraded password visibility toggle:
<AriaButton type="button" isDisabled={isDisabled} aria-label={isPasswordVisible ? "Hide password" : "Show password"} aria-pressed={isPasswordVisible} />
Resolved Defect Categories
  • ✓
    Trailing Padding Granted: Automatically assigns pr-9 (or pr-9.5) padding, preventing characters from sliding under the icon.
  • ✓
    Disabled State Synchronized: Eye toggle inherits isDisabled and disabled:pointer-events-none classes.
  • ✓
    Form Safety Guaranteed: Declaring type="button" eliminates accidental form submissions.
  • ✓
    Clean Numeric Interface: Removed unnecessary date imports from InputNumber.

6. Accessibility & Code Quality Enhancements

Enhancing WCAG compliance and developer ergonomics
ASSISTIVE TECH
Dynamic ARIA Announcements
aria-label={isPasswordVisible ? "Hide password" : "Show password"} aria-pressed={isPasswordVisible}
Screen readers announce toggle status dynamically when switching between masked and visible passwords.
FORM INTEGRITY
Accidental Submit Protection
type="button"
Standard HTML buttons inside forms default to submit. Explicitly defining type="button" avoids unintentional submissions.
STATE SYNC
Disabled State Synchronization
isDisabled={isDisabled} disabled:opacity-50 disabled:cursor-not-allowed
Disabled inputs propagate their state to the inner toggle button, rendering it non-clickable and dimmed.
TYPE SAFETY
TypeScript Interface Purity
// Removed from InputNumber: AriaDateFieldProps, DateValue
Eliminated copy-pasted date type pollution from InputNumber, keeping developer autocomplete clean and accurate.
