Mini Project • Identified Challenge

6. Experiment 10: Problem Statement

Security Audit
💥 1. Memory Exhaustion on Large Files
Naive file encryption loads the entire file into RAM at once. Encrypting large multi-gigabyte files (videos, ISOs, databases) triggers Out-Of-Memory crashes.
⚠️ 2. Lack of Authenticated Encryption (AEAD)
Unauthenticated ciphers allow attackers to flip bits in ciphertext. On decryption, corrupted data is produced without warning (Padding Oracle / Bit-Flipping attacks).
🔓 3. Weak Key Derivation & Reused Salts
Using plain text passwords or single-round SHA-256 leaves systems exposed to precomputed Rainbow Tables and rapid dictionary attacks.
⚙️ 4. Native Dependency Failures
Many cryptographic libraries rely on heavy native C/Rust binaries that fail to run on restricted enterprise environments or locked OS application policies.

Cryptographic Design

7. Experiment 10: Implementation & Architecture

Implementation
🔐 Authenticated Encryption (Encrypt-then-MAC)
• AES-256 CTR Mode: NIST FIPS-197 standard block cipher operating as a high-speed stream cipher.
• HMAC-SHA256: Cryptographic tag authenticating Magic Header, Salt, IV, and all Ciphertext bytes.
• PBKDF2-HMAC-SHA256: Derives dual 256-bit keys (Encryption + Authentication) using 600,000 iterations and a unique 16-byte random salt.
⚡ 64 KB Chunked Streaming Engine
• Streams input data in 64 KB chunks, maintaining strictly O(1) constant RAM footprint regardless of file size.
• Zero External Dependencies: Written cleanly in standard Python, running seamlessly on any platform without DLL restrictions.
Binary Header Format:
[MAGIC (8B: 'ROSPENC1')] + [SALT (16B)] + [IV (16B)] + [CIPHERTEXT (Chunks)] + [HMAC TAG (32B)]
